# GeoTax

نظام موبايل عربي لإدارة أعمال المأموريات الضريبية وربط الموظفين والممولين في منصة واحدة. يغطي التطبيق دورة العمل بدايةً من تسجيل وحصر الممولين ميدانيًا، مرورًا بالفحص والطلبات والمراسلات، وحتى التقارير وسجل العمليات.

بُني المشروع باستخدام **Expo SDK 57** و**React Native** و**TypeScript**، ويعتمد على **Supabase** للمصادقة وقاعدة البيانات والتخزين والتحديثات اللحظية.

## أهم المزايا

- واجهات عربية واتجاه من اليمين إلى اليسار.
- صلاحيات وشاشات رئيسية حسب الدور الوظيفي: الإدارة العليا، رئيس المأمورية، مدير الحاسب، مدير ومراجع ومأمور الحصر، مدير ومراجع ومأمور الفحص، والممول.
- فصل بيانات المأموريات وتطبيق صلاحيات الوصول عبر Row Level Security في Supabase.
- إدارة ملفات الممولين والبحث المركزي والاستيراد والحصر الميداني باستخدام الموقع والصور.
- إدارة الفروع والمخازن والأنشطة الفرعية والتعديلات على ملفات الممولين.
- إنشاء مهام الحصر والفحص وإسنادها ومتابعة حالتها وأولويتها.
- تسجيل المعاينات وطلبات الحضور والمواعيد والتوقف الجزئي أو النهائي للنشاط.
- بوابة للممول لعرض ملفه وتقديم الطلبات ومتابعتها.
- الشكاوى والأخبار والمراسلات والإشعارات داخل النظام.
- خريطة تفاعلية للممولين والفروع والمخازن مع تمييز حالة النشاط بالألوان.
- تقارير قابلة للتصفية والتصدير بصيغتي Excel وPDF.
- سجل تدقيق للعمليات وسجل منفصل لحذف الملفات.

## التقنيات المستخدمة

- [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/) وReact Native 0.86
- TypeScript
- React Navigation 7
- Supabase: Auth وPostgreSQL وStorage وRealtime وRLS
- خريطة Leaflet وOpenStreetMap داخل WebView (بدون مفاتيح)
- Expo Location وImage Picker وDocument Picker
- SheetJS وExpo Print وExpo Sharing لتصدير التقارير
- AsyncStorage لحفظ جلسة المستخدم محليًا

## متطلبات التشغيل

- Node.js وnpm
- مشروع Supabase
- حساب Expo عند إنشاء بناء سحابي باستخدام EAS
- هاتف فعلي أو محاكي Android/iOS

## البدء محليًا

1. ثبّت الاعتماديات:

   ```bash
   npm install
   ```

2. أنشئ ملف `.env` في جذر المشروع وأضف إعدادات البيئة:

   ```dotenv
   EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
   ```

3. جهّز قاعدة البيانات من ملفات SQL الموجودة داخل `supabase/`. ابدأ بالمخطط الأساسي، ثم طبّق ملفات المراحل المطلوبة بالترتيب. راجع [SETUP.md](SETUP.md) للحصول على خطوات إعداد Supabase والمصادقة والخرائط.

   > راجع أي ملف SQL قبل تشغيله على قاعدة بيانات تحتوي على بيانات فعلية؛ بعض ملفات الصيانة أو إعادة التهيئة قد تعدّل البيانات أو تحذفها.

4. شغّل خادم التطوير:

   ```bash
   npx expo start
   ```

يمكنك بعد ذلك فتح التطبيق على جهاز أو محاكي من واجهة Expo. لاختبار الخرائط والكاميرا والموقع والصلاحيات الأصلية بصورة مماثلة للإصدار النهائي، استخدم development build أو ملف APK مبنيًا عبر EAS.

## أوامر المشروع

```bash
npm start          # تشغيل Expo
npm run android    # فتح Android
npm run ios        # فتح iOS
npm run web        # فتح نسخة الويب
npx tsc --noEmit   # فحص TypeScript
```

## بناء APK عبر EAS

المشروع يحتوي على ملف `eas.json` وإعداد `preview` ينتج ملف APK للتوزيع الداخلي:

```bash
npx eas-cli login
npx eas-cli build --platform android --profile preview
```

لإنشاء بناء الإنتاج الداخلي:

```bash
npx eas-cli build --platform android --profile production
```

لا يحتوي `eas.json` على أي مفاتيح؛ كل إعداد بناء يقرأ متغيراته من بيئة EAS المطابقة (`preview` أو `production`). أضف المتغيرات مرة واحدة قبل البناء:

```bash
npx eas-cli env:set --name EXPO_PUBLIC_SUPABASE_URL --value "https://YOUR-PROJECT.supabase.co" --environment preview --environment production --visibility plaintext
npx eas-cli env:set --name EXPO_PUBLIC_SUPABASE_ANON_KEY --value "YOUR-ANON-PUBLIC-KEY" --environment preview --environment production --visibility sensitive
```

يفضل إدارة متغيرات البيئة الحساسة من خلال إعدادات بيئة EAS وعدم إضافة مفاتيح خاصة أو مفتاح `service_role` إلى المستودع. مفتاح Supabase المستخدم في التطبيق يجب أن يكون مفتاح العميل العام مع تفعيل سياسات RLS المناسبة.

```text

│   └── types.ts            # أنواع البيانات والأدوار والثوابت

├── eas.json                # إعدادات بناء EAS
└── SETUP.md                # دليل إعداد الخدمات الخارجية
```

## الأمان والبيانات

- لا تضع كلمات المرور أو مفتاح Supabase `service_role` أو مفاتيح غير مقيدة داخل الكود أو Git.
- ملف `.env` مستبعد من Git ويجب أن يبقى محليًا.
- استخدم سياسات RLS لعزل بيانات المأموريات وتحديد ما يستطيع كل دور قراءته أو تعديله.
- اختبر ملفات SQL على بيئة تجريبية وخذ نسخة احتياطية قبل تشغيل ملفات الصيانة على الإنتاج.
